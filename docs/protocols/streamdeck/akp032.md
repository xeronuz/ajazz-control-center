# AJAZZ AKP032 — 32-Key LCD Stream Dock

> 32-key desktop macro pad featuring a 4 rows x 8 columns LCD key grid on a
> 1024x600 display canvas. Uses 1024-byte packet framing with standard `CRT`
> vendor command opcodes.

| Connection                  | USB-C, wired                                                     |
| Input voltage               | 5 V via USB                                                      |
| LCD keys                    | **32**, arranged in **4 rows x 8 columns**                       |
| Key grid                    | 4 rows x 8 columns                                               |

## Layout sketch & Wire Key Remapping

```
+------+------+------+------+------+------+------+------+
| K01  | K02  | K03  | K04  | K05  | K06  | K07  | K08  |  <- Row 1 (UI Top)    -> HW display row 3, Input codes 1..8
+------+------+------+------+------+------+------+------+
| K09  | K10  | K11  | K12  | K13  | K14  | K15  | K16  |  <- Row 2             -> HW display row 2, Input codes 9..16
+------+------+------+------+------+------+------+------+
| K17  | K18  | K19  | K20  | K21  | K22  | K23  | K24  |  <- Row 3             -> HW display row 1, Input codes 17..24
+------+------+------+------+------+------+------+------+
| K25  | K26  | K27  | K28  | K29  | K30  | K31  | K32  |  <- Row 4 (UI Bottom) -> HW display row 0, Input codes 25..32
+------+------+------+------+------+------+------+------+
```

**[HARDWARE-CONFIRMED]**
- **Display Output:** The physical LCD panel addresses rows bottom-up: physical Row 0 is at the bottom of the device, and physical Row 3 is at the top. The software maps logical UI rows `0..3` to hardware display rows `3..0` (`hwRow = 3 - uiRow`, `hwKey = (3 - uiRow) * 8 + uiCol`).
- **Display Geometry & Key Centering:** The hardware LCD buffer divides the 1024x600 display into 128x128 px key cells ($1024 / 8 = 128$). Calibration confirmed the physical keycap aperture is ~104x104 px. The top bezel covers $Y=0..16$ while bottom $Y=124..127$ is visible, so a vertical offset of $Y=18$ centers the icon. Horizontally, Column 0 is bounded by the outer casing ($X=15$), while inner columns 1..7 are shifted rightward by the internal plastic grid ribs ($X=20$). The sidecar (`streamdock-host`) automatically composites incoming key images onto a native 128x128 frame with these exact offsets and margin fill, eliminating all bezel clipping and distortion.
- **Key Input:** The physical key matrix reports 1-based codes `1..32` top-to-bottom directly. No input row inversion is needed (`input_code = uiRow * 8 + uiCol + 1`).

## Wire Protocol

### Framing

All vendor control packets use 1024-byte payload framing (1025 bytes over
Windows `hidapi` with report ID `0x00`).

| Field                     | Bytes                       |
| ------------------------- | --------------------------- |
| Header prefix `CRT`       | 0..2 (`0x43 0x52 0x54`)     |
| Padding                   | 3..4 (`0x00 0x00`)          |
| 3-byte ASCII command word | 5..7                        |
| Padding                   | 8..9 (`0x00 0x00`)          |
| Command payload           | 10..1023 (zero-padded)      |

### Output Reports (Host -> Device)

| Command                        | Bytes 5..7       | Payload encoding                                                 |
| ------------------------------ | ---------------- | ---------------------------------------------------------------- |
| `DIS` — display init           | `0x44 0x49 0x53` | Wakes the LCD display from sleep/standby                         |
| `LIG` — set brightness         | `0x4C 0x49 0x47` | byte 10 = percent (`0..100`)                                     |
| `CLE` — clear keys             | `0x43 0x4C 0x45` | byte 11 = `0xFF` (clear all) or `1..32` (clear individual key)   |
| `BAT` — key JPEG image chunk   | `0x42 0x41 0x54` | bytes 10..11 = BE16 JPEG size; byte 12 = 1-based key index 1..32 |
| `STP` — flush / stop           | `0x53 0x54 0x50` | Completes transfer stream                                        |
| `CONNECT` — keep-alive         | ASCII `CONNECT`  | Periodic keep-alive heartbeat                                    |

### Image Upload

1. Host sends `BAT` header announce packet:
   - Byte 0..2: `'C'`, `'R'`, `'T'`
   - Byte 5..7: `'B'`, `'A'`, `'T'`
   - Byte 10..11: Big-endian 16-bit JPEG byte size
   - Byte 12: 1-based key index (`1..32`)
2. Host streams the JPEG payload in 1024-byte chunks (zero-padded to 1024 bytes).
3. Device renders the decoded JPEG into the target key's frame buffer without rotation (`Rot0`).

### Input Reports (Device -> Host)

Reports arrive on USB Interface 0 interrupt in pipe (64 or 512 bytes).
The firmware prefixes all input packets with `ACK\0\0OK\0\0`:

```
byte 0..2 : 'A', 'C', 'K' (0x41 0x43 0x4B)
byte 3..4 : 0x00 0x00
byte 5..6 : 'O', 'K' (0x4F 0x4B)
byte 7..8 : 0x00 0x00
byte 9    : key / rocker code:
            - 1..32 (0x01..0x20): Physical keys
            - 0x21 (33): Left wheel rocker UP (Previous Profile)
            - 0x22 (34): Left wheel center CLICK (Encoder 0 press)
            - 0x23 (35): Left wheel rocker DOWN (Next Profile)
            - 0x24 (36): Right wheel rocker UP (Previous Profile)
            - 0x25 (37): Right wheel center CLICK (Encoder 1 press)
            - 0x26 (38): Right wheel rocker DOWN (Next Profile)
byte 10   : event state (0x01 = pressed / deflected, 0x00 = released / neutral)
byte 11+  : 0x00
```
