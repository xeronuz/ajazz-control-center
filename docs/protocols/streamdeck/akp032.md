# AJAZZ AKP032 — 32-Key LCD Stream Dock

> 32-key desktop macro pad featuring a 4 rows x 8 columns LCD key grid on a
> 1024x600 display canvas. Uses 1024-byte packet framing with standard `CRT`
> vendor command opcodes.

## Hardware

| Property                    | Value                                                            |
| --------------------------- | ---------------------------------------------------------------- |
| Form factor                 | Desktop stream deck / macro controller                           |
| Connection                  | USB-C, wired                                                     |
| Input voltage               | 5 V via USB                                                      |
| LCD keys                    | **32**, arranged in **4 rows x 8 columns**                       |
| Key grid                    | 4 rows x 8 columns                                               |
| Display canvas              | 1024 x 600 px                                                    |
| Per-key image format        | JPEG (96x96, `Rot180`, `Mirror::None`)                           |
| Rotary encoders             | None                                                             |
| Touch strip                 | None                                                             |
| Backlight                   | LCD backlight brightness control (`CRT LIG`, 0..100%)            |
| Hardware IDs                | VID `0x0300`, PID `0x3016`                                       |
| USB Interface 0             | Vendor HID (`UsagePage 0xFFA0`, `Usage 0x0001`)                  |
| USB Interface 1             | Standard Keyboard + Consumer Control HID                         |
| Firmware observed           | `V4.AKP032.01.016`                                               |

## Layout sketch & Wire Key Remapping

```
+------+------+------+------+------+------+------+------+
| K01  | K02  | K03  | K04  | K05  | K06  | K07  | K08  |  <- Row 1 (UI Top) -> HW keys 24..31 (row 3)
+------+------+------+------+------+------+------+------+
| K09  | K10  | K11  | K12  | K13  | K14  | K15  | K16  |  <- Row 2          -> HW keys 16..23 (row 2)
+------+------+------+------+------+------+------+------+
| K17  | K18  | K19  | K20  | K21  | K22  | K23  | K24  |  <- Row 3          -> HW keys 8..15  (row 1)
+------+------+------+------+------+------+------+------+
| K25  | K26  | K27  | K28  | K29  | K30  | K31  | K32  |  <- Row 4 (UI Bottom)-> HW keys 0..7 (row 0)
+------+------+------+------+------+------+------+------+
```

**[HARDWARE-CONFIRMED]** The physical display panel and firmware address rows
bottom-up: physical Row 0 is at the bottom of the device, and physical Row 3 is
at the top. Columns run left-to-right (0..7) without inversion.
Therefore, the software maps logical UI rows `0..3` to hardware rows `3..0`:
`hwRow = 3 - uiRow`, `hwKey = (3 - uiRow) * 8 + uiCol`.

## Wire Protocol

### Framing

All vendor control packets use 1024-byte payload framing (1025 bytes over
Windows `hidapi` with report ID `0x00`).

| Field                     | Bytes                       |
| ------------------------- | --------------------------- |
| Header prefix `CRT`       | 0..2 (`0x43 0x52 0x54`)     |
| Padding                   | 3..4 (`0x00 0x00`)          |
| 3-byte ASCII command word | 5..7                        |
| Padding                   | 8..9 (`0x00 0x00`)          |
| Command payload           | 10..1023 (zero-padded)      |

### Output Reports (Host -> Device)

| Command                        | Bytes 5..7       | Payload encoding                                                 |
| ------------------------------ | ---------------- | ---------------------------------------------------------------- |
| `DIS` — display init           | `0x44 0x49 0x53` | Wakes the LCD display from sleep/standby                         |
| `LIG` — set brightness         | `0x4C 0x49 0x47` | byte 10 = percent (`0..100`)                                     |
| `CLE` — clear keys             | `0x43 0x4C 0x45` | byte 11 = `0xFF` (clear all) or `1..32` (clear individual key)   |
| `BAT` — key JPEG image chunk   | `0x42 0x41 0x54` | bytes 10..11 = BE16 JPEG size; byte 12 = 1-based key index 1..32 |
| `STP` — flush / stop           | `0x53 0x54 0x50` | Completes transfer stream                                        |
| `CONNECT` — keep-alive         | ASCII `CONNECT`  | Periodic keep-alive heartbeat                                    |

### Image Upload

1. Host sends `BAT` header announce packet:
   - Byte 0..2: `'C'`, `'R'`, `'T'`
   - Byte 5..7: `'B'`, `'A'`, `'T'`
   - Byte 10..11: Big-endian 16-bit JPEG byte size
   - Byte 12: 1-based key index (`1..32`)
2. Host streams the JPEG payload in 1024-byte chunks (zero-padded to 1024 bytes).
3. Device renders the decoded JPEG into the target key's frame buffer without rotation (`Rot0`).

### Input Reports (Device -> Host)

Reports arrive on USB Interface 0 interrupt in pipe (512 bytes):

```
byte 0..8 : 0x00
byte 9    : key index (1..32), or 0x00 for idle
byte 10   : key state (0x01 = pressed, 0x00 = released)
byte 11+  : 0x00
```
